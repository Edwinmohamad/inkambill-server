# INKAMBILL audit — 18 October 2026

Base: e7492fa7a7e806c6b031e09a769b9301ba33ad34.

## Findings and fixes

- Ordinary, forced, and period-wide cash deletion did not share the same guards. Bulk deletion could remove payment journals, warehouse-linked transactions, internal-transfer pairs, or locked-period records. All deletion paths now lock rows, check source and period, and retain a financial audit snapshot in the same database transaction. Ordinary bulk deletion still skips approved entries; forced deletion remains Master Admin only.
- Procurement cash entries use source_type=manual but are owned by a warehouse document. The manual edit/delete guard now checks warehouse references and transfer keys too.
- Data Kas offered edits/deletion for linked journals that the backend rejects. These entries retain details/proof/source navigation, with mutation buttons and selection checkboxes limited to standalone manual entries.
- Combined cash totals, expense charts, daily charts and reports counted internal site-transfer pairs as company income/expense. Consolidated views exclude internal-transfer pairs while individual-site views retain them.
- SQL DATE values in WhatsApp templates could render one day earlier under a server timezone west of UTC. Date-only strings retain their calendar date, and timestamps render in Asia/Jakarta.
- The optional dashboard billing promise had no immediate rejection handler. A failure now returns a complete unavailable monitor shape and displays a warning, avoiding an unhandled rejection or failed dashboard render from that optional component.
- Manual cash endpoints now enforce system-only category restrictions already reflected in the dropdown UI.
- Stale assertions for dashboard layout, NMS labels/palette, PSB non-cash policy, and WAHA log UI were updated to current behavior rather than restoring superseded product behavior.
- Dependency installation uses npm ci. Deployment validates the candidate image with the audit suite on an isolated network before backup/restart.

## Validation

- npm run test:audit: 49/49 test files pass, including syntax and static template checks.
- Cash deletion regression: 25 cases across single, bulk and period deletion; approved/non-approved behavior, Master Admin restriction, source protection, locked periods, audit failure, and rollback before partial deletion.
- Cash view rendering: manual, payment-linked, warehouse purchase, warehouse transfer and internal-pair fixtures; action visibility and EJS render checks.
- Date regression: UTC, Asia/Jakarta and America/Los_Angeles.
- Optional dashboard billing failure fallback tested with a rejected query stub.

Most application tests use isolated fixtures/mocks or static contracts. This audit does not establish that every production workflow is bug-free. No production financial data was mutated for testing. Live browser journeys and real router/WAHA integrations have not been exercised. A fresh installation also still depends on baseline database SQL files referenced by Compose but absent from this repository; this audit does not reconstruct that baseline schema.
